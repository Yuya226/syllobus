# Syllobus 友人テスト計画

作成：2026-11-27。対象は既存のCSV取り込み・卒業要件・成績表示。新しい履修推薦の開発より、使えるかの確認を優先する。

## 今回の実装範囲

- 取り込み確認で学部・学科／専攻・入学年度を設定。学科は既存の確認済み選択肢を使う。
- ダッシュボードに学科を表示。入力済みの条件を再利用する。
- 単位ペース・同期比較・科目分布・履修傾向を学部＋学科で分離する。
- 学科未入力・不明な自由入力・別学部の学科は公開集計に含めない。過去の値を勝手に変換しない。
- 公開基準は各集計で最低20セッションを維持。学部全体への自動的な条件拡大はしない。
- デモ、卒業要件を初期表示する3タブ、自動比較取得、任意の共有保存は維持する。

「同じ学科」は同じコース・専攻・適用要件まで保証しない。外国語の専攻、工学部・基礎工学部のコースなど、既存の選択肢で区別できない範囲は残る。今回の比較を履修推薦や卒業充足の根拠にしない。

## 今回は実装しないもの

不足区分への科目推薦、先輩の履修モデル、履修予定の保存・卒業見込みの再計算、今年の開講情報の自動収集。学科・年度の適用確認と十分な投稿が必要なため、友人テスト後に判断する。

## 参加者と進め方

開発者が友人3〜5人へ個別に依頼する。募集・送信はまだ行っていない。

- 中心：経済学部で入学年度の異なる2〜3人。現在の対応範囲で使い勝手と判定の一致を見る。
- 可能なら別学科のある学部の1〜2人。学科選択・対応範囲・未対応時の表示を確認する。
- iPhone／Android／PCを可能な範囲で分ける。全端末をそろえるために初回を延期しない。
- 1人15〜20分。最初は操作方法を説明せず、「卒業までに足りない単位を調べてみて」とだけ伝える。
- 初回は3人で実施し、重大な問題を直してから残りの人に試してもらう。

まずデモで試し、自分の成績を使うかは本人が選ぶ。標準手順では共有保存を選ばない。実データを使わなくても参加できる。

## テストでやってもらうこと

| 順番 | 課題 | 観察すること |
|---|---|---|
| 1 | デモを開き、卒業までに足りない区分を1つ探す | 説明なしで場所が分かるか。参考計算を卒業保証と誤解しないか |
| 2 | 希望者は自分の単位修得CSVを取得・取り込む | ガイド、ファイル選択、確認画面で止まらないか |
| 3 | 学部・学科・入学年度を選び、共有保存せず確定する | 選択肢が本人の所属に合うか。再入力を要求されないか |
| 4 | 元データと総修得単位・数科目の評語を本人が照合する | 欠落・重複・単位数の不一致がないか |
| 5 | 不足区分を1つ開き、自分の便覧・大学の確認表と照合する | 区分・必要数・年度が一致するか。不一致は箇所と理由を調べる |
| 6 | 成績分析・履修傾向を開く | 操作せず比較取得が始まるか。学科が示されるか |
| 7 | 設定を開閉し、再読み込みする | 所属と成績が保持され、モバイルで操作できるか |

3〜5人では20セッションの公開条件を満たさない。比較が空であることは正常で、埋めるために本番へ架空データを投入しない。科目推薦はまだないことも依頼時に伝える。

開発者側では別途、不正CSV→選び直し、同じファイルの再選択、学部変更時の学科リセット、未設定学科、少数集計、他セッションのアクセス拒否を確認する。実データの削除・共有保存を一般参加者の必須課題にしない。

## 回収するフィードバック

成績CSVや成績表の提出を求めない。開発者の手元で次の項目だけ記録する。

- テスター番号、端末・ブラウザ、学部・学科・入学年度（任意）
- 完了した課題、止まった場所、助けた回数、おおよその所要時間
- 「最初に何が分かった？」「分からなかった表示は？」「次の履修登録でも使いたい？ なぜ？」
- 不具合があれば、画面名・操作・期待結果・実際の結果
- 画像が必要な場合は、氏名・学籍番号・成績・セッション情報を隠した画面だけ

正確な成績値、氏名、学籍番号、端末内の保存情報、認証トークンは記録・公開しない。個人のテスト回答をGitHubへコミットせず、共有する課題には必要な再現条件だけ転記する。テストのための行動追跡ツールは新設しない。

## 改善の優先順位と完了条件

| 優先度 | 例 | 対応 |
|---|---|---|
| 最優先 | 他人の情報が見える、同意なく保存される、別学科の比較になる、卒業要件を誤って確定表示する | 実データのテストを止め、該当機能を修正・再検証する |
| 高 | CSVを選んでも進まない、成績や単位が欠落する、設定が消える | 次の参加者に依頼する前に直す |
| 中 | 不足区分を見つけにくい、説明が長い、操作を繰り返す必要がある | 複数人で観察されたものから削る・整理する |
| 後 | 履修推薦、計画保存などの新機能 | 今の体験が成立してから判断する |

初回の目安は「3人中2人以上が助けなしで不足区分を見つけられる」「希望者がCSV取り込みを完了できる」「確認した範囲で重大な計算・所属・データ保護の問題がない」。少人数で需要を証明したとは扱わない。不具合が見つかった経路は修正後に同じ手順で再確認する。

日程は参加者に合わせる。順序は、公開版確認 → 初回3人 → 不具合整理 → 修正 → 残りの参加者で再確認とする。

## そのまま送れる依頼文

> 阪大の成績CSVから、卒業までに足りない単位を確認するサービスを作っています。15分くらい試して、分かりにくいところを教えてもらえませんか？
>
> https://syllobus.com/dashboard?demo=1
>
> まずサンプルだけで大丈夫です。自分の成績で試す場合も、共有保存は任意で、CSVを僕に送る必要はありません。卒業要件は参考表示なので、便覧と違うところがあれば教えてください。先輩の履修候補を出す機能はこれからです。

## テスト後の判断

不足単位が分かることに価値を感じてもらえたら、不足区分を開いた際の先輩修得例を次の候補にする。科目推薦に進む前に、学科・コース・適用年度の互換性、公開可能な件数、科目名と単位数の整合性を確認する。投稿が足りなければ、無理に推薦機能を作らず、取り込みと卒業要件の改善を優先する。
